# Dynamic companion discovery

Selimbey works on its own. Add another capability only when the task needs a specialist outcome that Selimbey does not own.

Use the live capability catalog provided by the current host as the source of truth. Search names and descriptions for the required outcome, then read the complete instructions of the best match. Do not assume a particular skill name, file path, version, plugin, or router exists on another machine.

Possible specialist outcomes include:

- reproducing an interface from a supplied screenshot or visual reference;
- generating web or mobile design concepts as images;
- implementing complex, coordinated motion beyond the current stack’s simple transitions;
- creating a brand identity, logo, or other brand system material;
- producing a presentation deck; and
- running a formal UI guideline or accessibility audit.

Choose the narrowest compatible capability. Add one visual direction at most. Add motion, accessibility, or performance guidance only when the task needs it. If no suitable companion appears in the live catalog, continue with Selimbey and state the limitation only when it affects the requested result.

Companion discovery does not install skills, inspect private folders, change tool permissions, or authorize external actions.
