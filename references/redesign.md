# Redesign existing interfaces

Read this before a substantial change to an existing interface.

Inspect the current design language, behavior, content, assets, and constraints first. A refinement keeps the existing identity, information structure, behavior, and truthful copy outside the requested area. A redesign retains product facts and necessary flows while choosing a replacement visual direction.

Avoid an accidental halfway state. Improve the current system as a system, or replace it with a clear new one. Ask before changing factual copy, product claims, user-facing terms, or required flows.

Audit typography, hierarchy, layout, surfaces, spacing, color and contrast, navigation, feedback, responsive behavior, icons, semantics, and loading, error, and empty states. Keep observed problems separate from personal preference.

Work in the existing framework and with the available dependencies. Preserve working behavior during a visual change.

Prioritize improvements in this order:

1. Task flow, accessibility, feedback, and responsive failures.
2. Typography, hierarchy, content width, spacing, and color roles.
3. Repeated component states, surface language, icons, and interactions.
4. Generic patterns that do not suit the product.
5. Motion and expressive details.

Check repeated components for consistency. A redesign should remain familiar enough for current users to complete their work.
